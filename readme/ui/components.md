# UI components inventory

Three shared component folders: **`ui/`** (low-level shadcn-style Radix/cva primitives), **`common/`** (app-wide composed components) and **`layout/`** (page chrome). Feature-specific components live next to their feature in `src/features/<feature>/components/` (see the last table). All styling flows through the `cn()` helper (`src/lib/utils.ts`, `twMerge(clsx(...))`) and semantic Tailwind tokens; no hardcoded hex in component code.

### cva-driven primitives

Only `Badge` and `Button` use `class-variance-authority`. Both export their `*Variants` function (`badgeVariants`, `buttonVariants`) so other components can reuse the variant classes (`Calendar` and `Pagination` do). Every other primitive is a plain `forwardRef` + `cn()` wrapper with no variant object.

### Primitive notes

- Imports use **bare package names** (`lucide-react`, `@radix-ui/react-*`, `class-variance-authority`, `react-day-picker`, `date-fns`).
- `'use client'` is declared on the interactive Radix primitives (`Dialog`, `DropdownMenu`, `Label`, `Popover`, `Select`, `Switch`, `Tabs`, `Tooltip`), on `Calendar`, and on stateful `common/` components. `Input`, `Textarea`, `Badge`, `Button`, `Card`, `Table`, `Pagination`, `Skeleton`, `StatCard`, `StatusBadge` are server-safe (no directive). `FormInput` is a client component (`type="password"` holds show/hide state).
- **Button is the only loading-aware primitive**: it owns the inline ring spinner; `ConfirmDialog` forwards its `loading` straight to the confirm `Button`.
- Focus rings use `focus-visible:ring-ring ring-offset-background` so they track the active theme.

### Status badge mapping (`status-badge.tsx`)

`StatusBadge` reads a fixed `MAP: Record<string, { label, variant }>`. What NobleBid currently passes it:

| Caller | Statuses passed | Result |
|---|---|---|
| `/admin/members` | `ACTIVE` / `INACTIVE` (from `isActive`) | "Active" `success` / "Suspended" `secondary` |
| `/admin/payments` | `CREATED`, `PAID`, `FAILED` (upper-cased) | `CREATED` unmapped → `outline` "CREATED"; "Paid" `success`; "Failed" `destructive` |
| `/admin/commissions`, `/sell/commissions` | `DUE`, `PAID`, `WAIVED` | "Paid" `success`; `DUE` and `WAIVED` unmapped → `outline` with the raw string |

The full map: `success` for `APPROVED`, `VERIFIED`, `ACTIVE`, `PAID`, `COMPLETED`, `SENT`, `CLOSED`; `warning` for `PENDING`, `PENDING_APPROVAL`, `OPEN`, `INVESTIGATING`, `MEDIUM`; `destructive` for `REJECTED`, `EXPIRED`, `SUSPENDED`, `DELETED`, `FAILED`, `HIGH`, `CRITICAL`; `secondary` for `DRAFT`, `INACTIVE` (labelled "Suspended"), `PAUSED`, `CANCELLED`, `CONTAINED`, `LOW`. Most of these keys are not produced by any NobleBid status. Auction statuses do not go through `StatusBadge`: `AuctionStatusBadge` (`features/auctions/components/auction-card.tsx`) maps `LIVE` → "Live" `success`, `SCHEDULED` → "Upcoming" `warning`, `ENDED` → "Ended" `secondary`, `CANCELLED` → "Cancelled" `destructive`.

## Conventions

- **One component per file** as a rule (a few files export a small family, e.g. `document-upload.tsx`, `charts.tsx`, `pinch-zoom.tsx`); filename = component name in kebab-case, component in PascalCase.
- **Named exports** (`export function` / `export const`).
- **Props interface above the component**, named `<Component>Props` where a dedicated interface exists.
- **Use semantic Tailwind classes**, never hardcoded hex: `text-foreground`, `bg-background`, `text-destructive`, `bg-primary/10`, etc. (Tailwind colours map to `hsl(var(--token))`; see `readme/theming/tokens.md`.)
- **`cn()` everywhere**: every primitive merges its caller `className` last through `cn()` so overrides win without specificity fights.
- **Confirmations** always go through `common/ConfirmDialog`, never raw `ui/dialog` for a confirm, never `window.confirm` (`docs/CONFIRM_DIALOG.md`).
- **Theming** via `next-themes` only, no manual class toggling (`readme/theming/dark-mode.md`).
