# UI components inventory

Two component categories: **`ui/`** (low-level shadcn-style Radix/cva primitives) and **`common/`** (app-wide composed components). All styling flows through the `cn()` helper (`src/lib/utils.ts` — `twMerge(clsx(...))`) and semantic Tailwind tokens; no hardcoded hex in component code.

## `components/ui/` — primitives

### cva-driven primitives

Only `Badge` and `Button` use `class-variance-authority`. Both export their `*Variants` function (`badgeVariants`, `buttonVariants`) so other components/styles can reuse the variant classes. Every other primitive is a plain `forwardRef` + `cn()` wrapper with no variant object.

### Primitive notes

- Imports use **bare package names** (`lucide-react`, `@radix-ui/react-*`, `class-variance-authority`, `react-day-picker`, `date-fns`).
- `'use client'` is declared on the interactive Radix primitives (`Dialog`, `DropdownMenu`, `Label`, `Popover`, `Select`, `Switch`, `Tabs`, `Tooltip`), on `Calendar` (`react-day-picker`), and on stateful `common/` components. `Input`, `Textarea`, `Badge`, `Card`, `Table`, `Skeleton`, `StatCard`, `StatusBadge` are server-safe (no directive). `FormInput` is a client component (`'use client'`) — `type="password"` holds show/hide state.
- **Button is the only loading-aware primitive** — it owns the inline ring spinner; `ConfirmDialog` forwards its `loading` straight to the confirm `Button`.
- Focus rings use `focus-visible:ring-ring ring-offset-background` so they track the active theme.

### Status badge mapping (`status-badge.tsx`)

`StatusBadge` reads a frozen `MAP: Record<string, { label, variant }>`:

| Status keys | Badge variant |
|---|---|
| `APPROVED`, `VERIFIED`, `ACTIVE`, `CREDIT`, `PAID`, `COMPLETED`, `SENT` | `success` |
| `PENDING`, `PENDING_APPROVAL` | `warning` |
| `REJECTED`, `EXPIRED`, `DELETED`, `DEBIT`, `FAILED`, `SUSPENDED` | `destructive` |
| `REFUND`, `REFUNDED` | `default` |
| `PAUSED`, `ADJUSTMENT`, `CANCELLED`, `DRAFT`, `INACTIVE` | `secondary` |
| `CLOSED` | `success` |
| `OPEN`, `INVESTIGATING`, `MEDIUM` | `warning` |
| `CONTAINED`, `LOW` | `secondary` |
| `HIGH`, `CRITICAL` | `destructive` |
| _(unmapped)_ | `outline`, raw status as label |

`OPEN`/`INVESTIGATING`/`CONTAINED`/`CLOSED` are breach-incident case status; `LOW`/`MEDIUM`/`HIGH`/`CRITICAL` are breach severity — both reuse the one `MAP` since `StatusBadge` just keys on the raw string (see `readme/flows/breach-incidents.md`). Inquiries (`readme/flows/inquiries.md`) reuse `OPEN` and `CLOSED` the same way, so an open inquiry shows an amber "Open" badge and a closed one a green "Closed" badge; there are no inquiry-specific entries. `SENT` is a watchlist match-alert status, sharing `FAILED` with payments for the same reason (see `readme/flows/watchlist.md`).

## Conventions

- **One component per file**; filename = component name in kebab-case, component in PascalCase.
- **Named exports** preferred (`export function` / `export const`).
- **Props interface above the component**, named `<Component>Props` where a dedicated interface exists.
- **Use semantic Tailwind classes**, never hardcoded hex: `text-foreground`, `bg-background`, `text-destructive`, `bg-primary/10`, etc. (Tailwind colors map to `hsl(var(--token))` — see `readme/theming/tokens.md`.)
- **`cn()` everywhere** — every primitive merges its caller `className` last through `cn()` so overrides win without specificity fights.
- **Confirmations** always go through `common/ConfirmDialog` — never raw `ui/dialog` for a confirm, never `window.confirm` (hard rule 1, `docs/CONFIRM_DIALOG.md`).
- **Spec inputs** always go through `common/DynamicSpecField` (hard rule 9).
- **Theming** via `next-themes` only — no manual class toggling (hard rule 7; `readme/theming/dark-mode.md`).
