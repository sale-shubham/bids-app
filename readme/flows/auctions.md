# Auctions (browse, detail, selling)

Code: `src/features/auctions/`, pages `src/app/(public)/auctions/`, `src/app/(auctioneer)/sell/`. API side: `../bids-api/readme/flows/auctions.md`.

## App shell and the website
There is no Home page in the app: the landing page, About, How it works and Contact live in the separate `bids-website` repo, and `/` here is just `redirect('/login')` (signed-in users never see it). Browse and detail are public pages in `src/app/(public)/`, rendered inside the same `DashboardShell` as the signed-in area through `PublicShell` (`components/layout/public-shell.tsx`). Logged out they run in **guest mode**: nav = Auctions + Leaderboard, header "Log in" / "Sign up" (both carry `?next=<current page>`, `useAuthHref`), a "Log in" tab on the phone bottom bar, footer links (`ShellFooter`) to the website's About / How it works / Contact (absolute links from `NEXT_PUBLIC_WEBSITE_URL`) and the in-app legal pages. Guests can browse and watch live bids; bidding and watching send them to `/login?next=`. A signed-in member / admin sees their own nav on the same pages. Page bodies lay out with container queries (`@lg/content:` etc.), like every page in the shell.

## Browse (`/auctions`)
- Server-rendered first page + `generateMetadata`; then client `useInfiniteQuery` with key `['auctions', filters]` and `InfiniteScroll`. A client `RecentlyViewed` strip (device-local, see below) sits under the list.
- Filters live in the URL (`auctions.filters.ts`: `parseFilters` / `filtersToParams`, defaults omitted so URLs stay clean): `status` (`live` default, `upcoming`, `ended`), `q` (max 100 chars), `category`, `condition` (`NEW` / `USED`), `minPrice` / `maxPrice` in rupees, `verified=true` ("Verified sellers only" switch in `AuctionFilterBar`, sent as `verified=true`; omitted when off; not part of saved searches), `verified=true` ("Verified sellers only" switch in `AuctionFilterBar`, sent as `verified=true`; omitted when off; not part of saved searches), `sort` (`endingSoon` default, `newest`, `priceAsc`, `priceDesc`, `mostBids`). Unknown values fall back to defaults.
- `SaveSearchButton` (BIDDERs, when q / category / condition / price is set) next to "Clear filters" saves the filters as an alert (`saved-searches.md`).
- Categories: `useCategories()` (`['auctions', 'categories']`, stale 5 min).

## Selling (`/sell/*`, AUCTIONEER only)
- The platform maximum price comes from `GET /settings/public` (`maxPricePaise`, optional; falls back to `DEFAULT_MAX_PRICE_PAISE` = ₹10 crore) via `useMaxPricePaise()` (`features/settings/use-settings.ts`). `AuctionForm` passes it to `makeAuctionFormSchema(originalStart, maxPricePaise)`, which caps the starting bid and the minimum increment ("Starting bid can be at most ₹10,00,00,000"). The API's `PRICE_TOO_HIGH` error (`details.maxPaise`) is mapped by `auctionErrorMessage`. Amounts are bigint in the API but plain numbers in paise on the wire.
- `UnpaidCommissionBanner` sits in the auctioneer layout. `AuctionForm` blocks creating a new auction while `member.unpaidCommissionPaise > 0` and links to `/sell/commissions` (the API enforces the same rule).
- `/sell/new` and `/sell/auctions/[id]/edit` share `AuctionForm` (zod schema in `auctions.schema.ts`): title 5–120 chars, description 20–10,000 chars (rich text, sanitised by the API), category, condition `NEW` / `USED`, 1–8 images, starting bid and optional minimum increment (≥ ₹1) in rupees (converted to paise on submit), start now or at a date/time, preset duration or custom end. Pricing also has an optional hidden "Reserve price (₹)" ("Hidden from bidders. Below it, the item doesn't sell.") and "Buy It Now price (₹)" ("Bidders can buy instantly until the first bid."). Refines mirror the API: reserve >= starting bid; Buy It Now > starting bid and >= reserve when both set; both <= platform maximum. `toWritePayload` sends `reservePricePaise` / `buyNowPricePaise` (null when empty; `withoutNullPrices` drops them on create, edit sends null to clear). Edit pre-fills from `reservePricePaise` (seller/admin only field) / `buyNowPricePaise`. `INVALID_RESERVE` / `INVALID_BUY_NOW` are mapped in `auctions.errors.ts`.
- Relist: `/sell/new?from=<auctionId>` (`NewAuction` in `components/new-auction.tsx`) loads that auction with `useAuction` and, only if the viewer is its seller, pre-fills title, description, category, condition, images, starting bid, increment, reserve and Buy It Now (`relistFormValues`; dates reset to start now / 7 days). Otherwise a blank form.
- Images: `use-image-uploader` -> `use-upload` gets a presigned S3 URL (`POST /uploads/presign`) and PUTs the file directly; JPG / PNG / WebP, max 5 MB each, up to 8, first image is the cover. Before presigning, `resizeImage` (`features/uploads/resize-image.ts`) downscales to at most 2000 px on the longest side (EXIF orientation applied via `createImageBitmap`) and re-encodes to WebP at quality 0.85 (presigned as `image/webp`); it returns the original file when the browser lacks support or the result is not smaller. Because photos are shrunk first, the picker accepts originals up to 25 MB and the resized file must fit 5 MB (`prepareImage` in `use-upload.ts`).
- `/sell/auctions`: the seller's auctions (`['auctions', 'mine', status]`, infinite). Editable while `bidCount === 0` and SCHEDULED / LIVE; `RepublishDialog` for ENDED auctions with no bids; delete with `<ConfirmDialog>`.
- `/sell/auctions/[id]`: bids received and the result (winner contact after a sale, commission note).
- `/sell/auctions/[id]` also shows the reserve and Buy It Now prices to the owner and "Reserve met / not met".
- Mutations invalidate `['auctions']` and `['auction', id]`.

## Media: video and zoom
- Listing video: `VideoUploadField` (`components/video-upload-field.tsx`, props `value: string | null`, `onChange(url | null)`) picks one MP4 / WebM up to 50 MB (type and size checked client side), uploads it through the presign flow to folder `auction-videos` with a progress bar (`use-video-upload.ts`), previews it in `<video controls preload="metadata">` and can remove it. The API stores it as `videoUrl` (null clears); card DTOs carry `hasVideo`, detail carries `videoUrl`. The sell form must hold `videoUrl` and send it with the write payload.
- Detail: `AuctionGallery` shows the video (`controls preload="metadata" playsInline`) right under the image strip. `AuctionCard` shows a small video icon (bottom-left of the cover) when `hasVideo`.
- Zoom: clicking the main image or a thumbnail opens `yet-another-react-lightbox` with the Zoom plugin (pinch, scroll wheel, double click, swipe, arrow keys, Esc). Its stylesheet is imported in `auction-gallery.tsx`, like `react-quill-new`'s in the rich text editor. The old `ImageLightbox` component is no longer used by the gallery.

## Bulk upload (`/sell/bulk`, AUCTIONEER)
Code: `src/features/bulk/`, nav entry "Bulk upload" (auctioneer nav, under Sell). Flow: download the CSV template (`templateCsv()`: title, description, category, condition, startingBid, minIncrement, reservePrice, buyNowPrice, estimateLow, estimateHigh, startAt, durationHours, images) -> pick the CSV and the image files -> `parseCsv` (`papaparse`, headers matched case-insensitively, max 50 rows) and `mapRows` (rupees to paise, `startAt` "now" or ISO plus `durationHours` -> `startTime` / `endTime`, category sent as the name or slug for the API to resolve, up to 8 image names separated by `|`) -> preview table (`BulkPreviewTable`) with per-row client validation (the single-form rules) and unmatched image names (matched case-insensitively against the selected files) -> "Create N auctions" uploads each unique image once (resized, 3 at a time, "Uploading images 3 / 12") through `useUploadImage('auctions')`, then `POST /auctions/bulk { items }` (all or nothing). On success a list of the created auctions links to their pages. On `400 BULK_INVALID` the API's `details.rows[{ index, errors[{ field, message }] }]` is shown next to the matching rows and nothing was created; `429` shows "at most 5 bulk uploads per hour" (`bulk.errors.ts`). The submit button stays disabled while any row has a problem. "now" start times are resolved when the batch is submitted, after the uploads.

## Sold archive (`/sold`) and similar sold
- `/sold` (public, server-rendered first page, then infinite scroll via `AuctionList` with `SOLD_FILTERS` = `status=ended&sold=true&sort=recentlySold`) lists auctions that ended with a winner. `AuctionCard` shows "Sold for ₹X · <date>" (price = `currentBidPaise`, date = `endedAt`) when `sold`. In the nav as "Sold archive" (guest and member).
- Detail: `SimilarSold` ("Recently sold in this category", `GET /auctions/:id/similar-sold`, key `['auction-similar-sold', id]`, up to 6 cards) at the bottom of the page; hidden while loading, on error and when empty.

## Listing quality (Phase F, see `categories.md`)
- Sell form (`auction-form.tsx`, `auctions.schema.ts`): cascading category picker (`categoryId`) + dynamic attributes (`attributes`), condition select with 6 grades (`CONDITIONS` in `auctions.types.ts`: New, Like new, Good, Fair, Used, For parts / not working), optional estimate range (₹ low – high, both or neither, low <= high, >= ₹1 -> `estimateLowPaise`/`estimateHighPaise`), optional rich-text "Condition report" (same `RichTextEditor` as the description, <= 5,000 chars, empty Quill HTML is sent as `''`), "Delivery" section (Pickup + city, Courier + fee + ships within days; at least one; `shippingOptions`) and the optional video field. Edit and relist (`?from=`) pre-fill all of it (`defaultFormValues` / `relistFormValues`; legacy listings without `shippingOptions` default to courier). Edit sends only changed fields. New zod rules: category required, attributes per category schema, estimate pair, shipping rules, condition report length.
- Errors (`auctions.errors.ts`): `INVALID_CATEGORY`, `INVALID_ATTRIBUTES` (field errors mapped), `INVALID_ESTIMATE`, `INVALID_SHIPPING`.
- Browse: category by slug (tree select) + up to 3 `attr.<key>` selects (`AuctionFilters.attrs`, `parseFilters` / `filtersToSearchParams` / `auctionListParams`), condition filter with all 6 grades. Saved searches store the category slug and any of the 6 conditions.
- Detail (`listing-info.tsx`): category breadcrumb, "Estimate ₹X – ₹Y" under the bid panel, "Delivery" block (pickup city, courier fee or Free, ships within N days), "Specifications" table, collapsible "Condition report" (native `<details>`, `RichText`). Card: "Est. ₹X–₹Y" line when both bounds exist.
